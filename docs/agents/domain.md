# 도메인 문서

엔지니어링 스킬이 코드베이스를 탐색할 때 이 저장소의 도메인 문서를 읽는 방법.

이 저장소는 단일 컨텍스트 구성이다. 도메인 문서는 한국어로 쓴다.

## 탐색 전에 읽을 것

- 저장소 루트의 **`GLOSSARY.md`**
- **`docs/adr/`**: 작업하려는 영역에 닿는 ADR

파일이 없으면 **조용히 진행한다**. 없다고 지적하거나 미리 만들자고 제안하지 않는다. `/domain-modeling` 스킬(`/grill-with-docs`와 `/improve-codebase-architecture`를 통해 실행됨)이 용어나 결정이 실제로 확정될 때 만든다.

`projects/` 아래 서브모듈의 문서는 각 저장소의 것이며 이 저장소의 도메인 문서가 아니다.

## 파일 구조

```
/
├── GLOSSARY.md
└── docs/adr/
    ├── 0001-<slug>.md
    └── 0002-<slug>.md
```

## 용어집의 어휘를 쓴다

출력에서 도메인 개념을 부를 때(이슈 제목, 리팩터링 제안, 가설, 테스트 이름)는 `GLOSSARY.md`에 정의된 용어를 쓴다. 용어집이 명시적으로 피하는 동의어로 흘러가지 않는다.

필요한 개념이 용어집에 아직 없다면 그것이 신호다. 프로젝트가 쓰지 않는 말을 지어내고 있거나(다시 생각한다), 실제 공백이 있는 것이다(`/domain-modeling`에 넘길 것으로 적어 둔다).

## ADR과의 충돌은 드러낸다

출력이 기존 ADR과 어긋나면 조용히 덮어쓰지 말고 명시한다:

> _ADR-0007과 어긋나지만, 다시 열 만한 이유는…_
