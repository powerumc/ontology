# 기능은 루트 저장소가 지식 저장소에 복사하고, 지식 저장소의 커밋에는 넣지 않는다

지식 저장소에는 온톨로지 기능이 없다. 그래서 루트 저장소가 자기 `onto/`(코드, 공통 어휘, 구조 제약, 기본 규칙, 템플릿, 규약 문서)를 지식 저장소의 `.onto/`로 복사하고, 이 루트 관리 파일은 지식 저장소의 `.gitignore`로 제외한다. 지식 저장소 안에서도 같은 기능으로 그 저장소의 지식만 다룰 수 있게 하면서, 팀과 공유하는 저장소의 이력에 도구가 쌓이지 않게 하기 위해서다. 저장소별 차이는 저장소 소유 파일인 `ontology.yaml`에만 적는다.

## 검토한 대안

- **복사한 기능을 지식 저장소에 커밋하기**: 따로 클론해도 기능을 쓸 수 있지만, 저장소마다 도구 사본이 이력에 쌓이고 버전이 제각각 굳어서 기각했다.
- **기능을 복사하지 않고 루트 저장소에서만 실행하기**: 지식 저장소 안에서는 아무 기능도 쓸 수 없어서 기각했다.
- **공통 어휘를 별도 저장소나 패키지로 배포하기**: 중첩 서브모듈이나 설치 단계가 늘어나서 기각했다.

## 결과

- 에이전트 스킬(`.claude/skills/onto-*/`)도 같은 루트 관리 파일이다. 지식 저장소의 같은 위치로 복사하고 `.gitignore`로 제외한다. `.claude/skills/`에는 지식 저장소 팀의 스킬도 있을 수 있어, `onto-`로 시작하는 디렉토리만 복사하고 지우며 그 밖의 스킬은 건드리지 않는다.
- 루트 저장소의 `onto/`가 복사의 원본이고, 지식 저장소에서는 `.onto/`라는 숨김 디렉토리가 된다. 루트 저장소에서는 그것이 본체이고, 지식 저장소에서는 얹혀 있는 것이기 때문이다.
- 루트 관리 파일은 최신화 때마다 덮어쓰므로 손으로 고치면 안 된다.
- 지식 저장소를 따로 클론하면 복사된 기능이 없다. 그 상태에서는 인덱스와 페이지를 파일로 읽고, 기능을 쓰려면 루트 저장소에 붙여 최신화한다.
- 지식 저장소의 추적되는 파일 가운데 루트 저장소가 손대는 것은 `.gitignore`와 프로젝트 지침 파일의 표시된 블록뿐이다. `Justfile`은 건드리지 않으며, 지식 저장소 안에서는 `.onto/` 안의 `Justfile`을 직접 가리켜 실행한다.
- 최신화는 지식 저장소의 작업 트리만 바꾼다. 무엇을 커밋해 팀 저장소에 올릴지는 사람이 정한다.
