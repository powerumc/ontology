# 식별자는 URL이 아니라 경로에서 만든다

엔티티의 식별자는 지식 저장소 안에서의 페이지 상대 경로이고, 다른 지식 저장소의 엔티티는 `<저장소 이름>:<식별자>`로 가리킨다. RDF가 요구하는 절대 IRI는 루트 저장소의 도구가 컴파일할 때 붙인다. 에이전트가 식별자를 곧바로 파일로 열 수 있고, 지식 저장소 안에 외부 주소가 박히지 않기 때문이다.

## 검토한 대안

- **원격 저장소 URL이나 소유 도메인에서 파생한 base IRI**: 식별자가 파일 위치와 따로 놀고, 지식 저장소에 외부 주소가 박혀서 기각했다.
- **루트 저장소 기준 경로를 그대로 적는 교차 참조**: 지식 저장소에 루트의 디렉토리 구조가 박히고, 단독으로 열면 깨진 경로로 보여서 기각했다.

## 결과

- 페이지를 옮기거나 이름을 바꾸면 식별자가 바뀐다. 깨진 참조는 스크립트 검사가 잡는다.
- 지식 저장소의 이름은 고유해야 하고, 서브모듈 디렉토리 이름과 같아야 한다.
- 단독 상태에서는 교차 참조를 검사할 수 없다. 루트 저장소에서 전체를 합쳐 검사한다.
- 공통 어휘는 위치와 무관한 고정 네임스페이스 하나를 쓴다. 저장소마다 사본이 있어도 같은 클래스를 가리켜야 하기 때문이다.
