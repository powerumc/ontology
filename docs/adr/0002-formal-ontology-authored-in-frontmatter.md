# 정형 온톨로지(RDF)를 쓰되 frontmatter로 저작한다

지식을 RDF 그래프로 다뤄 질의(SPARQL), 구조 제약 검사(SHACL), 가벼운 추론(하위 클래스, 역관계, 추이 관계)을 할 수 있게 한다. 다만 사람과 LLM 에이전트가 같은 파일을 읽고 쓸 수 있도록, 페이지의 YAML frontmatter로 쓰고 JSON-LD context로 RDF에 매핑한다. 컴파일된 RDF는 커밋하지 않는다.

## 검토한 대안

- **링크만 있는 자유 형식 위키**: 기준 사례인 Karpathy의 LLM Wiki가 이 방식이다. 기계적으로 검사할 수단이 없다.
- **frontmatter에 타입만 두는 가벼운 체계**: 표준 질의와 추론을 쓸 수 없어 직접 만들어야 한다.
- **Turtle 직접 작성**: 본문과 분리되고 LLM과 사람이 쓰기 어렵다. 공통 어휘와 구조 제약의 정의에만 쓴다.
- **OWL 2 RL 전체 규칙**: 필요한 추론은 세 가지뿐인데, 페이지 3,000개에서 전체 규칙은 11.3초, 세 규칙만 직접 적용하면 1.1초였다. 검사와 푸시 관문마다 드는 시간이라 제외했다.
- **완전한 DL 추론**: 10~30개 저장소 규모에 비해 무겁다. 누락을 잡는 일은 열린 세계를 가정하는 OWL이 아니라 SHACL의 몫이라 제외했다.

## 결과

- 그래프가 필요한 작업(질의, 구조 제약 검사, 추론)은 기능이 있는 곳, 곧 루트 저장소와 루트 저장소에 붙은 지식 저장소 안에서만 된다.
- 페이지의 frontmatter 키는 JSON-LD context에 정의된 것만 쓸 수 있다.
