# 받기와 푸시

```sh
just git status          # 저장소별 미커밋, 미푸시, 뒤처짐 요약
just git pull            # 루트 저장소와 모든 지식 저장소를 fast-forward로 받습니다
just git push            # 스크립트 검사 뒤 모든 저장소를 푸시합니다
just git push --force    # 검사에 오류가 있어도 올립니다
```

## 받기

`pull`은 fast-forward만 합니다. 추적 브랜치에 있지 않거나 fast-forward가 되지 않는 지식 저장소는 건드리지 않고 건너뛰며 이유를 알려 줍니다. 루트의 서브모듈 포인터 변경은 커밋하지 않습니다.

## 푸시

`push`는 이미 커밋한 것만 올립니다. 지식 저장소를 먼저 하나씩 올리고, 모두 성공해야 루트 저장소를 올립니다. 현재 브랜치를 같은 이름의 원격 브랜치로 올리며, 미커밋 변경이 있는 저장소는 올리기 전에 목록으로 알려 줍니다.

## 푸시 관문

`push`는 올리기 전에 루트 저장소에서 스크립트 검사(`just onto validate`)를 실행합니다. 검사는 커밋된 내용이 아니라 작업 트리를 기준으로 합니다.

| 검사 결과 | `push`의 동작 |
|---|---|
| 오류가 있음 | 어떤 저장소도 올리지 않고 걸린 문제를 보여 준 뒤 1로 끝납니다. |
| 경고만 있음 | 경고를 보여 주고 올립니다. |
| 검사 도구를 실행하지 못함(`uv`가 없는 경우 등) | "검사 도구를 실행하지 못했다"며 푸시를 막습니다. 관문이 꺼져 있는지도 도구(`just onto rules`)가 읽기 때문에 켜진 것으로 봅니다. `--force`를 주면 이 경우도 넘기고 올립니다. |

### 건너뛰기와 끄기

`--force`(`-f`)는 관문만 건너뜁니다. 오류가 있어도 올리고, 관문을 건너뛰었다는 사실을 출력에 남깁니다. git의 강제 푸시와 달리 원격의 이력을 덮어쓰지 않습니다.

관문을 아예 끄려면 루트 기본 규칙([`onto/rules.yaml`](../../onto/rules.yaml))에서 `push-gate`의 `enabled`를 `false`로 합니다. 지식 저장소의 규칙으로는 끌 수 없습니다.

### 검사하지 않는 서브모듈

스크립트 검사는 `projects/` 바로 아래에 있는 숨김이 아닌 디렉토리만 지식 저장소로 봅니다. 그 밖에 직접 등록한 서브모듈은 검사 없이 올라가며, 푸시 전에 이름으로 알려 줍니다.

검사 관문은 이 명령 하나뿐입니다. git 훅과 CI는 두지 않았습니다.

## 에이전트에게 맡기기

이 작업에는 스킬이 없습니다. 루트 `CLAUDE.md`가 명령은 `just`라고 안내하므로, 루트 저장소에서 에이전트에게 말하면 에이전트가 위 명령을 찾아 실행합니다. 관문을 `--force`로 넘길지는 사람이 정합니다.

| 하고 싶은 것 | 이렇게 말합니다 |
|---|---|
| 상태 보기 | "모든 저장소의 상태를 요약해 줘" |
| 받기 | "모든 저장소를 최신으로 받아 줘" |
| 푸시 | "커밋한 것을 모두 푸시해 줘" |

푸시 관문에 걸리면 에이전트가 걸린 문제를 보여 줍니다. 출력을 읽는 법은 [스크립트 검사](validate.md#스크립트-검사)에 있습니다. 페이지 내용까지 점검하려면 "billing을 onto-lint로 점검해 줘"처럼 [LLM 검사](validate.md#llm-검사)를 맡깁니다.
