# 질의

```sh
just onto query 'SELECT ?e ?t WHERE { ?e a onto:Component ; dcterms:title ?t } ORDER BY ?t'
```

질의문은 작은따옴표로 감싸 하나의 인자로 넘깁니다. 실행할 때마다 현재 파일에서 다시 컴파일하므로 미리 `build`하지 않아도 되고, 하위 클래스, 역관계, 추이 관계가 추론된 그래프를 질의합니다. 결과의 엔티티는 파일 경로로 나오며 그 경로가 곧 페이지입니다.

## 에이전트에게 묻기

SPARQL을 몰라도 됩니다. 스킬 `onto-query`가 질문을 질의로 바꿔 실행하고, 결과에서 페이지로, 페이지에서 근거 원본 문서로 따라가 답합니다.

| 알고 싶은 것 | 이렇게 묻습니다 |
|---|---|
| 이름으로 찾기 | "인보이스와 관련된 페이지를 찾아 줘" |
| 의존 관계 | "결제 API에 직접 또는 간접으로 의존하는 컴포넌트는?" |
| 프로젝트 사이의 의존 | "billing은 어떤 프로젝트에 의존해?" |
| 적용되는 정책 | "결제 게이트웨이에 적용되는 정책을 보여 줘" |
| 결정과 그 결과 | "결제 데이터베이스로 PostgreSQL을 고른 이유와, 그 결정을 실행한 구현 결과를 알려 줘" |

Claude Code에서는 `/onto-query 결제 API에 의존하는 컴포넌트는?`처럼 바로 부를 수 있습니다. 여러 프로젝트를 가로지르는 질문은 루트 저장소에서 합니다. 지식 저장소 안에서는 그 저장소의 엔티티만 나옵니다.

질의하는 법, 클래스와 관계 목록, 자주 쓰는 질의는 [`onto-query` 스킬](../../.claude/skills/onto-query/SKILL.md)에 정리되어 있습니다.

## `build`가 만드는 것

```sh
just onto build
```

| 산출물 | 위치 | 커밋 |
|---|---|---|
| 컴파일한 그래프 | `onto/.build/graph.ttl` | 하지 않음 |
| 모든 지식 저장소를 모은 전체 인덱스 | `onto/.build/index.md` | 하지 않음 |
| 지식 저장소별 인덱스 | `projects/<이름>/docs/ontology/index.md` | 지식 저장소에 커밋 |

지식 저장소별 인덱스는 생성물이지만 지식 저장소만 클론한 사람의 진입점이라 커밋합니다([ADR 0006](../adr/0006-generated-index-is-committed.md)).
